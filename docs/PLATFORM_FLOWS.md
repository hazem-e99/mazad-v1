# توثيق شامل لمنصة مزاد (mazad-v1) — الأدوار، الصلاحيات، وكل الفلوز

> هذا التوثيق مبني على قراءة الكود الفعلي للمشروع (الموديلات، الـ API routes، صفحات الأدمن والصفحات العامة) بتاريخ 2026-08-24. أي تعديل مستقبلي على الكود لازم يترافق بتحديث هذا الملف.

---

## 1) نظرة عامة على المنصة

المنصة عبارة عن سوق لبيع/مزايدة **لوحات سيارات سعودية مميزة**. فيها ثلاث طرق أساسية للتعامل مع لوحة:

1. **سوق مباشر (Marketplace)**: المستخدم يعرض لوحته بسعر ثابت.
2. **طلب مزاد (Auction Request)**: المستخدم يطلب من الإدارة تشغيل مزاد للوحته.
3. **مزاد ينشئه المستخدم بنفسه**: بعد الموافقة على لوحته، المستخدم يقدر يفتح مزاد بنفسه (بشروط).

مفيش بوابة دفع أو حجز أموال داخل المنصة — البيع/الشراء يتم فعليًا **خارج المنصة عبر واتساب**، والمنصة فقط تكشف رقم التواصل بين البائع والفائز بعد اكتمال الصفقة.

## 2) الأدوار (Roles) وحالة الحساب

### 2.1 الأدوار الثلاثة

| الدور (role) | الوصف |
|---|---|
| `user` | مستخدم عادي (الافتراضي عند التسجيل) |
| `supervisor` | مشرف — صلاحياته محدودة بما يتم منحه يدويًا فقط، صفر صلاحيات افتراضية |
| `admin` | مدير كامل — **يتجاوز كل فحوصات الصلاحيات تلقائيًا** بغض النظر عن قائمة صلاحياته المخزّنة |

### 2.2 حالة الحساب (منفصلة عن الدور)

| الحالة | المعنى |
|---|---|
| `active` | نشط، يقدر يستخدم المنصة بشكل طبيعي |
| `suspended` | موقوف مؤقتًا |
| `disabled` | معطّل |
| soft delete (`deletedAt`) | الحساب محذوف منطقيًا (بياناته التاريخية زي المزايدات والمزادات تفضل محفوظة للسجل) |

تغيير حالة الحساب أو الدور يُطبَّق **فورًا** على أي طلب جديد (السيرفر يعيد قراءة الدور والصلاحيات من قاعدة البيانات في كل ريكوست، مش بس من التوكن)، يعني لو الأدمن أوقف مستخدم أثناء استخدامه، هيتأثر فورًا مش بعد ما يعمل تسجيل دخول جديد.

### 2.3 نظام الصلاحيات (Permissions)

فيه 18 صلاحية منفصلة، ويقدر الأدمن يمنحها لأي مستخدم (خصوصًا `supervisor`) بشكل مخصص من غير ما يغيّر الدور بالكامل:

| الصلاحية | تتيح لصاحبها |
|---|---|
| `auction:bid` | المزايدة على مزاد |
| `auction:buy` | الشراء المباشر (Direct Purchase) |
| `auction:create` | إنشاء مزاد لِلوحة يملكها |
| `auction:close_own` | إنهاء (تصفية) مزاده الخاص يدويًا قبل الموعد |
| `auction:sell` | (صلاحية بيع عامة — جزء من مجموعة صلاحيات البيع الأساسية) |
| `auction:manage` | إدارة كاملة لأي مزاد (اعتماد/رفض/تغيير حالة/إنهاء أي مزاد) |
| `plate:manage` | إدارة كاملة للوحات (CRUD)، بما فيها إنشاء لوحات تُعتمد تلقائيًا |
| `plate:create_featured` | تعليم لوحة كـ VIP أو مميزة (Featured) |
| `plate_logo:manage` | إدارة شعارات اللوحات |
| `category:manage` | إدارة تصنيفات اللوحات |
| `listing:moderate` | مراجعة/اعتماد/رفض الإعلانات المُقدَّمة من المستخدمين |
| `ownership_document:view` | الاطلاع على مستند إثبات الملكية الخاص بأي لوحة |
| `user:manage` | إدارة المستخدمين (الأدوار، الحالة، الحذف الناعم) |
| `vip:manage` | إدارة قسم اللوحات المميزة (VIP) |
| `ad:manage` | إدارة الإعلانات (Ads/Classifieds) |
| `site_settings:manage` | إدارة إعدادات الموقع (CMS، الهوية، الصفحات الثابتة) |
| `upload:manage` | إدارة الرفوعات/الملفات |
| `stats:view` | الاطلاع على لوحة الإحصائيات |
| `audit:view` | الاطلاع على سجل التدقيق (Audit Log) |

**الصلاحيات الافتراضية حسب الدور:**
- `user` → `auction:buy` + `auction:bid` فقط (أساسيات التصفح/المزايدة/الشراء)
- `supervisor` → لا شيء افتراضيًا، كل شيء يُمنح يدويًا من الأدمن
- `admin` → كل شيء (bypass كامل)

**من يدخل لوحة تحكم الأدمن (`/admin`)؟** أي حساب دوره `admin` أو `supervisor`، **أو** أي مستخدم عادي مُنِح صلاحية `stats:view` فقط (يقدر يشوف الداشبورد بدون أي صلاحية إدارية تانية).

## 3) دورة حياة "اللوحة" (Plate) — من الإضافة للاعتماد

### 3.1 من يقدر يضيف لوحة؟

أي مستخدم مسجّل دخول. فورم إضافة اللوحة (`/plates/new`) بيتكون من 7 خطوات:

1. **بيانات الإعلان**: عنوان، وصف، رقم تواصل، إيميل، حسابات سوشيال ميديا (اختياري).
2. **بيانات اللوحة**:
   - نوع الاستخدام (`usageType`): خاصة، نقل، خاصة نقل، تجارية، رياضية، دبلوماسية، مؤقتة.
   - **حالة خاصة**: لو النوع "رياضية" → الحروف تُدخل بالإنجليزي مباشرة فقط (بدون عربي).
   - غير كده: الحروف تُدخل بالعربي (من مجموعة 17 حرف رسمية مسموحة)، ويتم اشتقاق الحروف الإنجليزية تلقائيًا حسب **جدول الحروف الرسمي لوزارة الداخلية** (وليس أي تحويل عشوائي).
   - سلسلة اختيار مترابطة إجباريًا: **نوع الاستخدام → الشكل (Shape) → الشعار (Logo)** — كل خطوة معطّلة لحد ما تختار اللي قبلها. الأشكال المسموحة لكل نوع استخدام محددة (مثلاً "خاصة" تقبل كل الأشكال الثلاثة، "رياضية" تقبل عريضة ورياضية صغيرة فقط، والباقي عريضة فقط).
   - التصنيف (فردي/مزدوج/ثلاثي/رباعي)، الحجم (كبير/صغير)، تصنيف اختياري إضافي (Category).
3. **الوسائط**: صورة اللوحة (إجباري) + صورة مستند إثبات الملكية (إجباري لأي مستخدم عادي — غير مطلوب لو المُقدِّم موظف/أدمن).
4. **جاهزية البيع**: هل الاستمارة سارية؟ الفحص الدوري ساري؟ التأمين متوفر؟
5. **نوع التقديم**: 
   - `marketplace` = عرض بيع مباشر بسعر ثابت.
   - `auction_request` = طلب من الإدارة تشغيل مزاد له.
6. **التسعير**: السعر (إجباري لو `marketplace`)، أو "مبلغ عرض حالي" (اختياري، فقط لو `auction_request` — يُستخدم كمرجع للأدمن عند تحديد سعر الافتتاح).
7. **مراجعة وإرسال**.

### 3.2 ماذا يحدث بعد الإرسال؟

- أي إرسال من **مستخدم عادي** يدخل تلقائيًا في حالة `pending` (بانتظار المراجعة) — **حتى لو حاول يضيف اللوحة من مسار API مختلف**، السيرفر يفرض حالة `pending` دايمًا لمنع أي التفاف على المراجعة.
- إرسال من **موظف يملك `plate:manage`** يُعتمد تلقائيًا (`approved`) مباشرة.
- المستند الخاص بإثبات الملكية **لا يظهر لأي حد** غير: صاحب اللوحة نفسه، أو موظف يملك `plate:manage`، أو موظف يملك `ownership_document:view`.

### 3.3 حالات المراجعة (Moderation Status)

| الحالة | المعنى |
|---|---|
| `pending` | بانتظار مراجعة الإدارة |
| `approved` | تمت الموافقة، اللوحة ظاهرة للعامة |
| `rejected` | مرفوضة (مع سبب رفض إجباري يكتبه الأدمن) |

الانتقالات المسموحة: `pending → approved/rejected`، `approved → rejected`، `rejected → pending/approved` (يعني لو المستخدم عدّل وأعاد الإرسال بعد الرفض، ترجع `pending` من جديد تلقائيًا).

### 3.4 صفحة "إعلاناتي" (`/my-listings`)

المستخدم بيشوف كل لوحاته المُرسَلة مع:
- شارة حالة المراجعة (قيد المراجعة / معتمدة / مرفوضة).
- شارة نوع التقديم (سوق / طلب مزاد).
- شارة VIP لو مميزة.
- لو مرفوضة → رابط "إعادة التقديم" يودّيه لصفحة تعديل اللوحة، وحفظ التعديل يرجّعها `pending` تلقائيًا.
- لكل لوحة يظهر هل زر "إنشاء مزاد" متاح، ولو لأ يوضح السبب (غير معتمدة / مخفية / يوجد مزاد نشط بالفعل لنفس اللوحة).

## 4) فلو إنشاء مزاد بواسطة المستخدم نفسه

المسار: `/my-listings/[plateId]/auction/new`

### 4.1 الشروط (يتم التحقق منها في السيرفر دايمًا، مش بس في الواجهة)

يجب أن تكون اللوحة:
- مملوكة فعليًا لنفس المستخدم صاحب الجلسة.
- في حالة `approved`.
- ظاهرة (`isVisible = true`).
- **بدون** مزاد آخر لنفس اللوحة في حالة `draft` أو `scheduled` أو `live` (مزاد نشط واحد فقط لكل لوحة في نفس الوقت).

### 4.2 بيانات الفورم

- سعر الافتتاح (`startingPrice`) — افتراضي 1000.
- الحد الأدنى للزيادة (`minIncrement`) — افتراضي 50.
- وقت البداية ووقت النهاية (افتراضيًا: يبدأ بعد 5 دقائق وينتهي بعد 24 ساعة).
- تفعيل اختياري لـ "الشراء المباشر" مع تحديد سعره.

### 4.3 ماذا يحدث عند الإرسال؟

- المزاد يُنشأ دايمًا في حالة **`draft`** (بمعنى "بانتظار مراجعة الإدارة" — استخدام مختلف عن معنى draft العادي للمزادات اللي ينشئها الأدمن).
- التصنيف (`category`) يُفرض دايمًا `regular` بغض النظر عن أي شيء (المستخدم العادي **لا يقدر** ينشئ مزاد "حصري/exclusive").
- لو رفع صورة خلفية مخصصة لصفحة المزاد، تدخل هي كمان في مراجعة منفصلة (`backgroundStatus: pending`).

### 4.4 اعتماد المزاد من الأدمن

من صفحة `/admin/auctions/[id]`، الأدمن يقدر:
- **الموافقة**: المزاد ينتقل من `draft` إلى `scheduled` (بعدها الجدولة التلقائية تُفعّله لـ `live` أوتوماتيكيًا عند وصول وقت البداية).
- **الرفض**: المزاد ينتقل إلى `cancelled`.

## 5) دورة حياة المزاد (Auction) بالكامل

### 5.1 الحالات (Status)

| الحالة | المعنى |
|---|---|
| `draft` | مسودة / بانتظار موافقة الأدمن (لو أنشأه مستخدم) |
| `scheduled` | معتمد ومجدول، لسه لم يبدأ |
| `live` | نشط الآن، تقبل مزايدات |
| `ended` | انتهى (حالة وسيطة نادرة الاستخدام) |
| `sold` | بيع بنجاح لأعلى مزايد |
| `unsold` | انتهى بدون بيع (لا يوجد مزايدات كافية) |
| `purchased` | تم شراؤه مباشرة (Direct Purchase) دون انتظار انتهاء المزاد |
| `cancelled` | أُلغي |

### 5.2 الانتقالات المسموحة (State Machine)

- `draft → scheduled | cancelled`
- `scheduled → live | cancelled`
- `live → sold | unsold | purchased | cancelled`
- `ended / sold / unsold / purchased / cancelled` → **نهائية**، لا يوجد أي انتقال بعدها.

⚠️ **قاعدة مهمة**: لا يمكن لأي أحد (حتى الأدمن) أن "يعيّن" حالة `sold` أو `unsold` مباشرة عبر تعديل يدوي — هاتين الحالتين تُحسبان فقط تلقائيًا عبر عملية "الإنهاء" (finalize)، لضمان عدم التلاعب بنتيجة المزاد.

### 5.3 من ينشئ المزادات وكيف؟

| المُنشئ | الصلاحية المطلوبة | القيود |
|---|---|---|
| مستخدم عادي (مالك اللوحة) | `auction:create` (بدون `auction:manage`) | لوحته فقط، معتمدة، ظاهرة، لا يوجد مزاد نشط سابق — يبدأ دايمًا `draft`، والتصنيف `regular` إجباريًا |
| موظف/أدمن | `auction:manage` | أي لوحة، أي تصنيف (`regular` أو `exclusive`)، يبدأ مباشرة `live` أو `scheduled` حسب وقت البداية |

### 5.4 التفعيل والإنهاء التلقائي

يعمل السيرفر على "نبضة" كل 5 ثوانٍ:
- **التفعيل**: أي مزاد `scheduled` تعدّى وقت بدايته → يتحول تلقائيًا إلى `live`.
- **الإنهاء**: أي مزاد `live` تعدّى وقت نهايته → تُحسب النتيجة تلقائيًا (بيع أو بدون بيع) حسب القاعدة:
  - **بيع** إذا وُجد مزايد أعلى والسعر الحالي أعلى من سعر الافتتاح.
  - **بدون بيع** إذا لم تُقدَّم أي مزايدة فعلية غيّرت السعر.

### 5.5 الإنهاء اليدوي (قبل الموعد)

يقدر يُنهي المزاد يدويًا قبل معاده:
- **موظف يملك `auction:manage`**: أي مزاد.
- **مالك اللوحة نفسه** لو يملك `auction:close_own`: مزاده هو فقط (يتم التحقق من الملكية في السيرفر مرة أخرى).

الإنهاء اليدوي **لا يختار نتيجة مختلفة** — هو فقط يُشغّل نفس حساب "بيع/بدون بيع" بشكل مبكر، مع إمكانية كتابة سبب حر اختياري.

## 6) فلو المزايدة (Bidding)

### 6.1 الشروط الأساسية

- يحتاج صلاحية `auction:bid` (متاحة افتراضيًا لكل مستخدم `user`).
- المزاد لازم يكون `live` وداخل الفترة الزمنية بين وقت البداية والنهاية.
- المبلغ المُقدَّم يجب أن يكون **≥ السعر الحالي + الحد الأدنى للزيادة** الخاص بهذا المزاد.
- فيه حد أقصى لعدد المحاولات: 20 مزايدة كل 10 ثوانٍ لكل مستخدم (حماية من السبام).

### 6.2 حماية من "السرقة اللحظية" (Anti-Sniping)

لو حد قدّم مزايدة خلال آخر **30 ثانية** من وقت انتهاء المزاد، يتم **تمديد وقت النهاية 60 ثانية إضافية تلقائيًا** — عشان يدي فرصة عادلة لباقي المزايدين للرد.

### 6.3 التعامل مع التسابق (Race Condition)

لو مستخدمين قدّموا مزايدة في نفس اللحظة تقريبًا، السيرفر يستخدم تحديث ذري (atomic) يعيد التحقق من السعر/الحالة وقت الكتابة الفعلية. اللي يخسر السباق تُسجَّل مزايدته كمرفوضة (`accepted:false`, سبب: "سبقتك مزايدة أخرى") ويظهر له تنبيه فوري.

### 6.4 التحديث اللحظي (Real-time)

كل حدث (مزايدة مقبولة، مزاد بدأ، مزاد انتهى، شراء مباشر) يُبَث فورًا لكل من يشاهد صفحة المزاد عبر Socket.IO — بما في ذلك عدّاد "عدد المشاهدين الآن" لكل مزاد.

### 6.5 لوحة المزايدة (BidPanel) — ما يراه المستخدم

- السعر الحالي والعدّاد التنازلي لحظيًا.
- سجل المزايدات مع تحميل المزيد (pagination).
- حقل إدخال مزايدة بأزرار +/- تبدأ افتراضيًا من (السعر الحالي + الحد الأدنى للزيادة).
- زر "شراء مباشر" (لو مفعّل على المزاد ويملك المستخدم صلاحية `auction:buy`).
- تنبيهات فورية: "تم تجاوز مزايدتك"، "تم قبول مزايدتك"، "تم البيع"، "بدون بيع"، "تم الشراء المباشر".

## 7) الشراء المباشر (Direct Purchase)

- يتاح فقط إذا فعّله منشئ المزاد (`directPurchaseEnabled = true`) وحدّد سعرًا (`directPurchasePrice`).
- يتطلب صلاحية `auction:buy`.
- متاح فقط والمزاد `live`.
- عند الشراء: المزاد ينتقل فورًا وبشكل ذري إلى `purchased`، يُسجَّل المشتري والسعر النهائي ووقت الشراء، ويُنشأ سجل "Purchase" مستقل، ويُبَث الحدث لحظيًا لكل المشاهدين.

---

## 8) بعد البيع — التواصل بين الطرفين

المنصة **لا تعالج أي دفع** ولا تحجز أموال. بعد ما تصير حالة المزاد `sold` أو `purchased`:
- **البائع** يشوف رقم تواصل **الفائز/المشتري**.
- **الفائز/المشتري** يشوف رقم تواصل **البائع**.
- يظهر زر واتساب مباشر (يتم تنسيق الأرقام السعودية تلقائيًا لصيغة `wa.me`) لبدء المحادثة وإتمام الصفقة يدويًا خارج المنصة.

---

## 9) صفحة المزاد العامة — ماذا يرى كل نوع مستخدم؟

في صفحة `/auctions/[id]`:
- **أي زائر**: مواصفات اللوحة، رسم توضيحي رسمي للوحة (رسم مُولَّد، مش صورة اللوحة الحقيقية المرفوعة)، حالة المزاد، شارات VIP/حصري لو منطبقة.
- **صاحب اللوحة (البائع)**: إن كان يملك `auction:close_own` ومزاده `live`، يظهر له زر "إنهاء المزاد الآن" + إمكانية رفع صورة خلفية مخصصة لصفحة المزاد (تدخل مراجعة إدارية منفصلة).
- **بعد البيع فقط**: تظهر معلومات التواصل كما بالبند 8.

---

## 10) الإعلانات المُصنَّفة (Ads / Classifieds)

قسم منفصل عن "اللوحات" — إعلان عام (عنوان، وصف، صورة، رابط، سعر، رقم تواصل) قد يرتبط اختياريًا بلوحة. يخضع لمراجعة إدارية (`ad:manage`) من خلال `/admin/ads` عبر تفعيل/تعطيل (`AdModerationToggle`).

## 11) VIP والمميز (Featured) والمزادات الحصرية (Exclusive)

| الميزة | من يملك صلاحية التفعيل | أين تظهر |
|---|---|---|
| VIP (`isVip`) | صاحب `plate:create_featured` فقط | `/vip`، شريط VIP في الهيدر |
| مميز (`isFeatured`) | صاحب `plate:create_featured` فقط | الصفحة الرئيسية (قسم "أحدث اللوحات المميزة") |
| مزاد حصري (`category: exclusive`) | صاحب `auction:manage` فقط | `/auctions/exclusive` |

المستخدم العادي **لا يقدر** يفعّل أي من الثلاثة لنفسه مهما كانت لوحته مميزة فعلًا — لازم موظف يملك الصلاحية المطلوبة يفعّلها له.

## 12) الشات العام

صفحة `/chat` — دردشة عامة واحدة لكل زوار/مستخدمي الموقع (مش خاصة لكل مزاد أو بين مستخدمين). محدودة بمعدل 10 رسائل كل 10 ثوانٍ لكل مستخدم لمنع السبام، وتُبث لحظيًا عبر Socket.IO. لا يوجد نظام رسائل خاصة بين المستخدمين.

## 13) لوحة تحكم الأدمن — صفحة بصفحة

الوصول لـ `/admin` بالكامل مقتصر على: دور `admin`، دور `supervisor`، أو أي حساب يملك `stats:view`.

| الصفحة | الصلاحية المطلوبة | الوظيفة |
|---|---|---|
| `/admin` (الرئيسية) | دخول عام للوحة التحكم | إحصائيات سريعة + نشاط حديث + بث لحظي للمزايدات الجارية |
| `/admin/listings` | `listing:moderate` أو `plate:manage` | قائمة انتظار مراجعة الإعلانات المُقدَّمة (فلترة حسب الحالة والنوع)، اعتماد/رفض مع سبب، وتحويل "طلب مزاد" معتمد إلى إنشاء مزاد فعلي |
| `/admin/auctions` | `auction:manage` | إدارة كل المزادات: اعتماد/رفض مزادات المستخدمين، إنهاء يدوي، إنشاء مزاد جديد مباشرة |
| `/admin/plates` | `plate:manage` | إدارة كاملة (CRUD) لكل اللوحات في النظام |
| `/admin/plate-categories` | `category:manage` | إدارة تصنيفات اللوحات |
| `/admin/plate-logos` | `plate_logo:manage` | إدارة الشعارات، وتحديد أنواع الاستخدام/الأشكال المسموح دمجها مع كل شعار |
| `/admin/users` | `user:manage` | قائمة المستخدمين، بحث/فلترة، تعديل الدور والصلاحيات (`UserRoleEditor`)، تعليق/تفعيل/حذف ناعم |
| `/admin/users/[id]` | `user:manage` | تعديل تفصيلي لمستخدم واحد (الاسم، الإيميل، الحالة، الصلاحيات الأساسية الخمسة) |
| `/admin/bids` | صلاحية عرض عامة (تتبع نفس بوابة `/admin`) | سجل/بث كل المزايدات على مستوى المنصة |
| `/admin/vip` | `vip:manage` | إدارة اللوحات المميزة VIP |
| `/admin/ads` | `ad:manage` | مراجعة/تفعيل/تعطيل الإعلانات المصنّفة |
| `/admin/stats` | `stats:view` | رسوم بيانية وإحصائيات المنصة |
| `/admin/audit` | `audit:view` | سجل تدقيق كامل لكل الإجراءات الإدارية (فلترة حسب الإجراء/الكيان) |
| `/admin/site-settings` | `site_settings:manage` | إدارة الهوية البصرية، الصفحة الرئيسية، SEO، عناصر التنقل، الفوتر، والصفحات الثابتة (`/pages/[slug]`) |

### 13.1 فروق مهمة بين تعديل صلاحيات من `UserRoleEditor` مقابل `UserDetailEditor`

- **`UserRoleEditor`** (من قائمة المستخدمين): محرر كامل — يغيّر الدور نفسه، ولو الدور `supervisor` يظهر checklist بكل الـ 18 صلاحية، بالإضافة لمفتاح تفعيل/تعطيل الحساب.
- **`UserDetailEditor`** (من صفحة تفاصيل مستخدم واحد): محرر أضيق — الاسم/الإيميل/الحالة + فقط الصلاحيات الخمسة الأساسية المتعلقة بالمزادات (`buy/sell/bid/create/close_own`). لو الدور `admin`، خانات الصلاحيات تظهر معطّلة/إعلامية فقط لأن الأدمن أصلًا يتجاوز كل الفحوصات الفردية.

## 14) ملخص: مين يقدر يعمل إيه ومين مش يقدر

### مستخدم عادي (`user`) — بدون أي صلاحيات إضافية مُمنوحة يدويًا

**يقدر:**
- يتصفح المزادات واللوحات المعروضة.
- يسجّل لوحة جديدة (تدخل مراجعة إجبارية).
- يعدّل/يعيد تقديم لوحته المرفوضة.
- ينشئ مزادًا للوحته الخاصة بعد اعتمادها (يدخل هو الآخر مراجعة، ويبدأ `draft` بانتظار موافقة الأدمن، وتصنيفه `regular` إجباريًا).
- يزايد على أي مزاد `live` (`auction:bid` متاحة افتراضيًا).
- يشتري مباشرة أي مزاد مفعّل عليه شراء مباشر (`auction:buy` متاحة افتراضيًا).
- يشوف رقم تواصل الطرف الآخر بعد اكتمال صفقة بيع/شراء تخصه.
- يستخدم الشات العام.

**لا يقدر:**
- يعتمد لوحته أو مزاده بنفسه (لازم مراجعة إدارية).
- ينشئ مزاد "حصري" (Exclusive) — يُفرض عليه `regular` دايمًا.
- يعلّم لوحته كـ VIP أو مميزة.
- ينهي مزاده يدويًا (إلا لو مُنِح صراحة `auction:close_own`).
- يشوف مستند إثبات ملكية لوحة غيره.
- يدخل أي صفحة من صفحات `/admin` (إلا لو مُنِح `stats:view`).
- يشوف رقم تواصل أي طرف قبل اكتمال البيع فعليًا.

### مشرف (`supervisor`) بدون صلاحيات مُمنوحة

عمليًا لا يقدر يعمل أي شيء إداري ولا حتى المزايدة الأساسية — كل شيء لازم يُمنح له صراحة صلاحية بصلاحية من الأدمن. الاستخدام النموذجي: يُمنح مجموعة صلاحيات محددة (مثلاً `listing:moderate` فقط، أو `stats:view` + `audit:view` فقط) ليقوم بدور محدد دون صلاحيات كاملة.

### أدمن (`admin`)

يتجاوز كل فحص صلاحية فردي تلقائيًا — يقدر يعمل أي حاجة في المنصة بلا استثناء: إدارة المستخدمين والأدوار، اعتماد/رفض اللوحات والمزادات والإعلانات، إنشاء مزادات حصرية أو VIP فورية بلا مراجعة، الاطلاع على أي مستند ملكية، إنهاء أي مزاد يدويًا، تعديل إعدادات الموقع بالكامل، ومراجعة سجل التدقيق.

## 15) قواعد عمل رئيسية (Business Rules) يجب تذكّرها

- الحد الأدنى الافتراضي لزيادة المزايدة: **50** (قابل للتخصيص لكل مزاد).
- نافذة الحماية من المزايدة اللحظية (Anti-Snipe): مزايدة خلال آخر **30 ثانية** تمدّد المزاد **60 ثانية**.
- مزاد نشط واحد فقط لكل لوحة في نفس الوقت (لا يمكن فتح مزاد جديد للوحة عليها مزاد `draft/scheduled/live` بالفعل).
- حالتا `sold` و`unsold` لا تُكتبان يدويًا أبدًا — فقط عبر آلية "الإنهاء" (finalize) المحسوبة تلقائيًا.
- كل إرسال لوحة من مستخدم عادي يدخل `pending` حتمًا، ولا يوجد أي مسار API يسمح بتجاوز هذه المراجعة.
- مستند إثبات الملكية إجباري لأي تقديم عام لعرض بيع أو طلب مزاد (غير مطلوب من الموظفين).
- قفل الحساب تلقائيًا لمدة 15 دقيقة بعد 5 محاولات دخول فاشلة متتالية.
- التسجيل الذاتي (Register) ينشئ الحساب دايمًا بدور `user` بدون أي صلاحيات إضافية.
